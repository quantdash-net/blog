回测结果对不齐，很多时候不是信号公式写错，而是拿来计算的那列价格并不是当时的成交价，或者最后一根 K 线还在更新。本文只列出 QuantDash 文档已经足够支撑的取数问题，以及必须用假数据才能讲清的算法差别。不使用未合并的回测示例，也不报告任何策略的收益率。

参数本身见 [复权参数和时间戳](/posts/kline-adjust-and-timestamps/)。入库前的结构检查见 [K 线质量检查](/posts/kline-quality-checks/)。不同来源的单位见 [文档对照](/posts/document-compare-tushare-akshare-quantdash/)。

## 收盘前的最后一根日 K 还在变

[FAQ](https://docs.quantdash.net/zh-Hans/faq.md) 写明：实时行情快照约 3 秒刷新一次，K 线数据盘中实时更新。快照的 3 秒是刷新间隔，不是某次请求的耗时，也不能用来判断一根日 K 是否已经收完。

文档没有“这根 K 线是否已完成”的字段，也没有写日 K 的 `timestamp` 对应开盘、收盘还是交易日零点。交易时段以交易所规则为准，不要把某个钟点写死成接口参数。可以做的是：在研究“已收盘的日收益”时，去掉交易日等于当前市场日期的那一行，等收盘后再单独补。当前市场日期用代码后缀对应的时区计算，和 SDK 0.1.0 显示 `trade_date` 的方式一致。

```python
# local-check
def completed_sessions(rows: list[dict], session_date: str) -> list[dict]:
    """去掉 trade_date 等于当前交易日的行。不判断当时是否已经收盘。"""
    return [row for row in rows if row["trade_date"] != session_date]
```

这只解决“不要把今天这一行放进已完成样本”。它不知道现在是不是收盘后。收盘后若仍去掉当天，样本会少一天，需要在确认收盘后再把该行加回去。

`end_time` 是闭区间。官方示例在设置某一天的结束时间后，示例表格包含了这一天。在还没打印真实 `timestamp` 之前，不要用“15:00 的毫秒”去猜边界。先取少量数据，看 `timestamp` 落在哪一分钟，再决定端点。本文没有 Key，没有做这个打印。

省略 `count` 和起止时间时，OpenAPI 的 `count` 默认是 100，最大 10000。一段号称覆盖多年的回测，如果请求里没有区间，实际可能只有最近 100 根。

## 前复权价格不是当时的成交价

默认 `adjust` 是 `forward`，文档的解释是比例复权，适合计算收益率。比例法改变的是除权前的价格水平。用这列价格去比较“当时能不能以 10 元买入”，比的是调整后的数字，不是当时的挂单价。要看成交价，请求里写 `adjust="none"`。

差值复权适合文档所说的绝对价差。两种算法在除权前的收益率可以不同。下面仍是假设价格：除权前是 20 和 22，除权日是 11。比例法把除权前乘 0.5，差值法把除权前减 11。

```python
# local-check
def simple_returns(prices: list[float]) -> list[float | None]:
    out: list[float | None] = [None]
    for prev, cur in zip(prices, prices[1:]):
        out.append(cur / prev - 1)
    return out
```

比例序列 `[10, 11, 11]` 的第一段收益是 10%，与不复权的 `22/20 - 1` 相同。差值序列 `[9, 11, 11]` 的第一段收益是 `11/9 - 1`。最后一段里，不复权从 22 到 11 会把价格跳变算进去。这组数字只说明“先选定算法再算收益”，不是 QuantDash 的复权实现，也不是回测业绩。

`ex_factor` 的算式没有在文档中公布。回测代码不要自行发明一个乘法去替代 `adjust` 参数。需要点对点的历史价格时，保留 `adjust="none"` 的原始序列，并把当时能知道的因子日期单独记下。因子接口支持用 `end_time` 过滤，这只说明可以按时间截取因子记录，不说明截取之后应该怎么乘。

AKShare 的日线页面写明，前复权历史价会在新的除权之后变化，长期分红的序列还可能出现负价格。那是 AKShare 对自己的前复权的说明。QuantDash 文档没有写负价格，也没有写本地保存的 `forward` 结果是否会在下次除权后失效。保存文件时写上 `adjust` 和下载日期，下次用新的除权因子日期核对，而不是默认文件仍然有效。

## 今天的标的池不是历史成分

`qd.quotes.get(universes=["CN_Stock"])` 取的是实时行情快照，文档中的标的池 `CN_Stock` 表示当前的 A 股（沪深京）。用这次返回的代码列表去拉多年日 K，研究样本就是“现在仍在这个池子里的标的”。文档没有提供历史成分接口，也没有说明退市代码是否还能用 `klines.get` 查询。元数据里的 `listing_date` 只在返回了该字段时才能用来看上市日，它不是退市日。

因此，当前快照适合盘中观察，不适合直接当作多年回测的股票池。股票池若来自别处，在文中写明来源和截止日期。

## 成交额单位不能沿用另一家的文档

把多个来源接进同一个回测时，单位要先对齐。[Tushare daily](https://tushare.pro/document/2?doc_id=27) 写明成交量是手、成交额是千元，并且该接口是未复权。[AKShare 的 stock_zh_a_hist_em](https://akshare.akfamily.xyz/data/stock/stock_quote.html) 写明成交量是手、成交额是元。QuantDash 的 `volume` 和 `amount` 没有单位说明。

官方示例里有一条日内 VWAP：`amount / (volume * 100)`。那是 [示例代码页](https://docs.quantdash.net/zh-Hans/sdk/python-examples.md) 中的表达式，不是字段单位定义。在单位被写进字段说明之前，回测不要借用这个 100，也不要把 Tushare 的千元换算套到 QuantDash 的 `amount` 上。

涨跌幅同样容易差一个数量级。快照字段 `ext.change_pct` 在 SDK 快速开始的示例中以小数出现。展示成百分比时再乘 100。不要把这个小数和 Tushare `daily` 里已经是百分数的 `pct_chg` 放进同一个阈值。

## 时间戳跨市场不能共用一个日历日

同一毫秒，按 `.SH` 格式化与按 `.US` 格式化，可以落在不同的日历日。写作环境是 UTC 时，上海 2026-05-01 零点的毫秒是 `1777564800000`；这个毫秒在美东是 `2026-04-30 12:00:00`。换算过程见 [复权参数和时间戳](/posts/kline-adjust-and-timestamps/)。

多市场回测若先把所有 `timestamp` 转成 UTC 的日期再对齐，A 股和美股的“同一天”会对错。对齐键应使用各自市场时区下的交易日，并且在会话没有重叠时不要把两根 K 线当成同时可交易。

## 问答

**问：默认前复权能不能直接算日收益率？**
答：文档把比例前复权描述为适合计算收益率。这不表示该列等于当时成交价。比较绝对价格或下单价时使用 `adjust="none"`。

**问：快照约 3 秒刷新一次，能不能说明日 K 每 3 秒收盘一次？**
答：不能。3 秒是实时快照的刷新间隔。日 K 是否已经完成，文档没有对应字段。

**问：用 CN_Stock 拉到的历史 K 线，是否包含退市股票？**
答：文档没有说明。`CN_Stock` 出现在实时行情的标的池说明里。退市标的能否按代码查询，需要另作确认，本文没有查询。

> 文中的价格序列是为了说明复权算法差别而设的假数据，不是回测结果。QuantDash 的口径以 [中文文档](https://docs.quantdash.net/zh-Hans) 为准。
